# Chrome-расширение для hh.ru — план

> Главная задача следующего этапа. Цель: убрать ручное копирование между кокпитом
> и hh.ru — агент работает прямо на странице вакансии.

## Идея в одном абзаце

Расширение для Chrome, которое подключается к уже работающему локальному кокпиту
(`http://127.0.0.1:8899`) и прямо на hh.ru показывает: насколько вакансия подходит,
почему, каких навыков не хватает, что спросят на интервью — и **готовит письмо,
подставляя его в форму отклика**. Финальную кнопку «Откликнуться» нажимаю я.

Ключевая экономия: не нужно переключаться между кокпитом и hh, копировать письма
руками и вручную отмечать отправленное — всё в одном окне.

## Что расширение делает

### На странице поиска (`hh.ru/search/vacancy`)
- Рядом с каждой вакансией — бейдж с процентом совпадения и категорией 🟢🟡🔴
- Неподходящие приглушаются, подходящие подсвечиваются
- Кнопка «в очередь» — добавить в список на разбор

### На странице вакансии (`hh.ru/vacancy/*`)
Сайдбар-панель с тем же, что сейчас в кокпите:
- % совпадения навыков и достоверность оценки
- «Почему подходит» и красные флаги
- Пробелы в навыках + сколько часов подтянуть
- «Что точно спросят на интервью»
- Готовое сопроводительное письмо (без длинного тире) с кнопкой **«Вставить в форму»**
- Адаптированное под вакансию резюме

### Учёт
- После моего отклика — кнопка «✓ Отправлено», запись сразу летит в локальную базу
- Воронка ведётся автоматически, руками ничего не отмечаю

## Чего расширение НЕ делает (и почему)

**Не нажимает «Откликнуться» за меня и не рассылает отклики пачкой.**

Причины, по которым эта граница стоит осознанно:

1. **Правила hh.ru.** Автоматизированные действия от имени пользователя запрещены.
   Расплата — блокировка аккаунта, вместе со всей историей откликов и резюме.
2. **На той стороне живые HR.** Массовая автоотправка — это спам реальным людям,
   и он бьёт по репутации отправителя, а не по площадке.
3. **Контроль над тем, что уходит от моего имени.** Письмо генерирует модель;
   один взгляд перед отправкой ловит ошибки, которые дороже сэкономленных секунд.

Это тот же принцип «Режим 1: агент готовит — я подтверждаю», который уже зашит
в кокпит. Расширение убирает всю рутину до последнего клика — сам клик остаётся мой.

Обход антибот-защиты, эмуляция «человеческих» задержек и подобное — не делаем.

## Техническая архитектура

```
Chrome Extension (Manifest V3)
├── content-script.js   работает на hh.ru: читает вакансию из DOM,
│                       рисует панель, подставляет письмо в форму
├── service-worker.js   фоновая логика, кэш оценок, связь с кокпитом
├── panel/              UI панели (HTML+CSS, без фреймворков — как весь проект)
└── manifest.json       права: hh.ru + localhost:8899

          ↕ fetch (JSON)

Локальный кокпит (уже написан, Node.js, порт 8899)
└── НОВОЕ: JSON API поверх существующего движка
```

**Главное решение: не дублировать логику.** Скоринг, словарь навыков, генерация
писем и адаптация резюме уже написаны в `src/scoring.mjs`, `src/skills-dict.mjs`,
`src/letters.mjs`, `src/resume.mjs`. Расширение — тонкий клиент, вся логика
остаётся в одном месте.

### Что дописать в кокпите (`src/cockpit.mjs`)

Новые эндпоинты:

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/score` | принять `{title, description, skills, salary, experience}` → вернуть оценку, причины, пробелы |
| `POST` | `/api/letter` | сгенерировать письмо под конкретную вакансию |
| `POST` | `/api/resume` | адаптированное резюме |
| `POST` | `/api/applied` | отметить отклик отправленным (запись в воронку) |
| `GET` | `/api/profile` | текущий профиль (для отображения в панели) |

Плюс **CORS**: разрешить origin `https://hh.ru` (сейчас кокпит отвечает только своей HTML-странице).

### Порядок работы

1. Дописать JSON API в кокпит + CORS, проверить через `curl`
2. Каркас расширения (manifest, service worker, загрузка в Chrome в режиме разработчика)
3. Content-script: вытащить данные вакансии из DOM hh.ru (заголовок, описание, навыки, зарплата)
4. Панель на странице вакансии: оценка, причины, пробелы
5. Письмо + кнопка «Вставить в форму»
6. Бейджи в поисковой выдаче
7. Кнопка «Отправлено» → запись в воронку

### Риски и подводные камни

- **hh.ru меняет вёрстку** — селекторы отвалятся. Уже наступали на это с парсером
  (перешли на числовые HTML-сущности). Решение то же: не падать молча, показывать
  «не смог разобрать страницу», а не тихо выдавать пустую оценку.
- **Кокпит должен быть запущен** — расширение без него бесполезно. Нужен понятный
  индикатор «кокпит недоступен» вместо пустой панели.
- **Не открывать кокпит наружу ради расширения** — расширение работает на том же
  компьютере, `127.0.0.1` достаточно.

## Статус (23.08.2026)

**Готово:**
- JSON API в кокпите (`src/cockpit.mjs`): `GET /api/profile`, `POST /api/score`,
  `POST /api/letter`, `POST /api/resume`, `POST /api/applied` + CORS только для `https://hh.ru`.
  Логика не задублирована: `/api/score` использует те же `weightOf`/`categorize` из
  `scoring.mjs`, что и `match.mjs`; `/api/letter` и `/api/resume` вызывают
  экспортированные `buildLetter()` (`letters.mjs`) и `tailor()` (`resume.mjs`) напрямую.
  Все 5 эндпоинтов проверены через `curl`.
- Каркас расширения в `extension/`: `manifest.json` (MV3, без background),
  `content.js`, `panel.css`. Работает только на `hh.ru/vacancy/*`.
  Селекторы DOM (`data-qa="vacancy-title"`, `vacancy-description`,
  `vacancy-company-name`, `skills-element`) сверены на живой странице hh.ru.
  Панель справа: 🟢/🟡/🔴, % совпадения, красные флаги, письмо в textarea
  с кнопкой «Скопировать», «✓ Отправлено» / «✗ Пропустить» → пишут в БД
  через `/api/applied`. **Кнопки «Откликнуться» нет и не будет** — см. раздел выше.
  При недоступном кокпите или незнакомой вёрстке страницы — явное сообщение
  об ошибке в панели, не тихий сбой.

**Не проверено вживую:** загрузка расширения в реальный Chrome и сквозной
прогон на живой вакансии — не было прямого доступа к браузеру пользователя
в сессии, где это писалось. Нужно загрузить вручную (`chrome://extensions` →
режим разработчика → «Загрузить распакованное расширение» → папка `extension/`)
и проверить, что панель появляется и письмо генерируется.

**Дальше, если понадобится:** бейджи в поисковой выдаче (шаг 6 из плана выше) —
пока не сделаны, панель работает только на странице конкретной вакансии.

# Калибровка скоринга — план (после накопления откликов)

Сейчас все оценки (приоритет, шанс HR, вероятность приглашения) — **эвристики**, помечены
как таковые в кокпите. Точными они станут, только когда появятся реальные исходы. Данные
для этого уже собираются с первого отклика — их нельзя восстановить задним числом.

## Что уже фиксируется

При каждом отклике (`status = sent`) в `Application.appliedSnapshot` пишется JSON:
`score, tier, category, stars, hrLevel, confidence, salaryNet, experience, letterLen,
hasResume, matchedSkills, missing, appliedAt`. Это «замороженная» оценка на момент отклика —
даже если позже пересчитается match, снимок остаётся.

Воронка (`ApplicationEvent`): `matched → sent → viewed → interview → offer / rejected`,
у пропусков и отказов — `reason` (ручная обратная связь).

## Когда что делать (по числу реальных исходов)

- **30 откликов** — глазами найти грубые ошибки: куда уходят отказы, какие tier'ы не отвечают.
- **50–70** — скорректировать веса вручную (какие факторы реально коррелируют с приглашением).
- **100+** — простая **логистическая регрессия** (не ML-комбайн): `invited ~ score + hrLevel +
  salaryMatch + freshness + coverLetterUsed + roleCategory`. Понятнее и объяснимее.
- **200+** — сравнить эвристику с моделью по метрикам ниже.

## Метрики (когда есть исходы)

- **Приглашения на 10 качественных откликов** — главная метрика продукта.
- **Reliability diagram** (калибровочная кривая): среди вакансий с прогнозом ~70% приглашение
  должно случаться ~в 70%. Только после этого можно снова показывать точные проценты.
- **Brier score** — точность вероятностных прогнозов.
- **Precision@10** — доля приглашений среди топ-10 по приоритету.
- **Конверсия по tier'ам** (🟢/🟡/🟠) — оправдывают ли себя категории.

## Пока данных нет

Не показываем точные проценты как прогноз. Приоритет — звёздами, шанс HR — уровнем
(высокий/средний/низкий), везде метка «эвристика». Единственный «настоящий» процент —
«совпадение навыков» (детерминированный расчёт, не предсказание).
